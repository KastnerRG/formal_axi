# Reproducible formal runs

Run the default C0/C5 FIFO configuration with:

```sh
tools/run_formal.sh
```

Select the checker level explicitly when comparing protocol-only and full
transaction closure:

```sh
LEVEL=protocol tools/run_formal.sh
LEVEL=full tools/run_formal.sh
```

The script sources `~/bashrc-new` without printing it, pins the Questa binary
directory, enters `shell.nix`, creates a never-overwritten directory below
`work/runs/`, compiles, proves, exports counterexample and cover VCDs, and
performs a non-GUI structural inspection of every exported VCD.

Configuration is passed as environment variables.  For example:

```sh
VENDOR=pulp IMPL=axi_fifo FIFO_DEPTH=4 FIFO_FALL_THROUGH=1 \
  tools/run_formal.sh
```

The full FIFO configuration surface is:

- `FIFO_DEPTH`: the storage-depth setting passed to the DUT.
- `FIFO_TRACK_DEPTH`: checker capacity when the wrapper contains additional
  elastic stages (Taxi uses `FIFO_DEPTH+2`).
- `FIFO_FALL_THROUGH`: selects the DUT's fall-through mode.
- `FIFO_ALLOW_BYPASS`: permits a same-cycle input/output transfer in the
  checker (Taxi's response path can bypass even in its registered setting).
- `MAX_STALL`: maximum cycles from VALID to READY. It is assumed for
  environment-driven READY and asserted for DUT-driven READY.
- `MAX_OUTSTANDING`: common read/write transaction-model capacity, passed as a
  typed AXI FVIP parameter.
- `MAX_AW_AHEAD`, `MAX_W_AHEAD`, and `MAX_BURST_LEN`: explicit transaction
  model-capacity bounds. At a FIFO output, each AW/W skew capacity is composed
  as the input bound plus `FIFO_DEPTH` because the channels are buffered
  independently.
- `MAX_RESPONSE_DELAY`: endpoint bound for first and subsequent R-beat
  availability after AR, and B availability after completed AW+W.
- `MAX_WRITE_DATA_DELAY`: endpoint AW-to-W progress bound, distinct from the
  AW/W skew-capacity limits.
- `MAX_ROLE_DELAY`: selected FIFO occurrence input-to-output progress bound.
- In the FIFO aggregate, DUT-owned response/write-data progress uses
  `outer delay + 2 * MAX_ROLE_DELAY`; the configured outer delay still applies
  directly to the environment-owned endpoint behavior.
- `ENABLE_BOUNDED_ENV`: enables endpoint READY/response/write-data progress and
  FIFO-role progress. Set it to zero for the safety-only profile.
- `LEVEL`: `protocol` compiles out cross-channel transaction tracking; `full`
  enables the production selected-occurrence transaction checkers. Exact
  oracles are available only in `fvip_validation/`.
- `FORMAL_TIMEOUT`: optional QVerify duration such as `300`, `5m`, or `1h`;
  QVerify then terminates cleanly and writes complete inconclusive summaries.
- `FORMAL_JOBS`: QVerify worker count, defaulting to `32`. Override it when a
  host or license requires a smaller proof-engine portfolio.

The four FIFO structural settings are typed top-level parameters on the common
`tb_fifo` harness. Depth and fall-through are passed from that harness into the
selected role wrapper; tracker depth and bypass remain checker parameters.
QVerify applies the Make/environment values with top-level `-G` overrides, so
none of these settings is a global SystemVerilog macro.

Run the curated suites with:

```sh
fvip_validation/tools/run_link_mutations.sh
fvip_validation/tools/run_fifo_mutations.sh
fvip_validation/tools/run_transaction_mutations.sh
tools/run_fifo_matrix.sh
```

The matrix defaults to the C5 closure profile: `MAX_STALL=0`,
`MAX_OUTSTANDING=1`, `MAX_AW_AHEAD=1`, `MAX_W_AHEAD=1`, and
`MAX_RESPONSE_DELAY=16`, `MAX_WRITE_DATA_DELAY=16`, and
`MAX_ROLE_DELAY=100`, with a five-minute per-run timeout. ZIPCPU and PULP
retain the eight-beat burst profile. Taxi's combined transaction run defaults
to one beat through `TAXI_TRANSACTION_MAX_BURST_LEN=1`; its eight-beat result
is reported separately as bounded/inconclusive.

Every run generated by the current runner contains `manifest.env`, the exact
`command.txt`, generated `flist.f`, the raw transcript/report,
`property_status.csv`, `vacuity_status.csv`,
`summary.json`, and `vcd_inventory.csv`. `vacuity_status.csv` classifies each
enabled assertion as `nonvacuous` or `unreachable`; `summary.json` records the
completed and total vacuity counts. The report step fails if Questa does not
finish every vacuity check. A nonzero exit also means compilation failed, a
property was fired/inconclusive/skipped, or an exported VCD could not be
parsed. The FIFO harness enables its bounded environment by default; use
`ENABLE_BOUNDED_ENV=0` when an unrestricted AXI compliance run is required.
The manifest records which profile was used.

Assertion antecedents do not get duplicate covers when vacuity analysis is
conclusive. A nonvacuous result is positive reachability evidence; an
unreachable result is an explicit classification under the recorded profile.
Unconditional assertions are active on every enabled sample and have no
antecedent to cover. Explicit covers remain for useful scenarios such as
backpressure, FIXED/WRAP bursts, W-before-AW, selection rank, and completion.
Optional assertions that do not elaborate are feature-disabled: transaction
tracking in `LEVEL=protocol`, and exclusive/ATOP semantics in the current FIFO
profile.

The executed C0-C5 results and their exact artifact directories are recorded in
[`c0_c5_execution.md`](c0_c5_execution.md).  In particular, the scripts treat
fired and inconclusive properties as nonzero exits; an intentionally bounded or
manually capped run is never silently promoted to a full proof.

The pre-C6 architecture gate closed in
`work/runs/20260901_arch_fifo_formal_05` with depth 2, `MAX_STALL=0`, one
outstanding transaction, 16-cycle outer response/write-data bounds, and a
16-cycle role bound. All 163 assertions proved and all 231 targets resolved.
Its companion link, transaction, and FIFO mutation artifacts are
`work/runs/20260901_arch_link_04`, `work/runs/20260901_arch_txn_mut_02`, and
`work/runs/20260901_arch_fifo_mut_02`.

The unified-channel readability refactor closed in
`work/runs/20260901_unified_channel_fifo_formal_01` under the same profile. All 89
assertions proved and all 157 targets resolved; 53 covers were reached and 15
were proven unreachable. Bundling rule fields reduced assertion target count
without removing checked signals. The 10 vacuous assertions are the five
VALID-stall and five payload-stall bundles expected with `MAX_STALL=0`; reset
checks are nonvacuous. The zero-warning link polarity run is
`work/runs/20260901_unified_channel_link_mut_02`, the 15-scenario transaction score
is `work/runs/20260901_unified_channel_txn_mut_01`, and the seven-scenario FIFO score
is `work/runs/20260901_unified_channel_fifo_mut_01`.

The reachability audit is reproduced by:

- `work/runs/20260901_reachability_fifo_zipcpu_protocol_s8_final`: protocol,
  `MAX_STALL=8`, 69/69 assertions proven and nonvacuous, all 36 covers reached.
- `work/runs/20260901_reachability_fifo_zipcpu_full_s0_b8`: full eight-beat
  closure, 89/89 assertions proven and 89/89 vacuity checks resolved. The ten
  unreachable triggers are exactly the VALID/payload stall checks disabled by
  the zero-stall policy; 53 covers are reached and 15 are classified
  uncoverable.

The one-beat full `MAX_STALL=8` stress profile now closes in one fresh run:

- `work/runs/20260901_close_fifo_zipcpu_full_s8_b1_j32` used `FORMAL_JOBS=32`
  and a 20-minute cap without changing any protocol, capacity, burst, or
  progress bound.
- All 157 targets resolved in 248 seconds: 85 nonvacuous assertions proved,
  four one-beat WRAP assertions were classified unreachable/vacuously proven,
  52 covers reached, and 16 covers were proven unreachable. There are zero
  fired or inconclusive targets, and all 89 vacuity checks completed.
- Peak use was 32 cores and 23.5 GB aggregate memory; the largest engine used
  1.5 GB.

The earlier 8-job runs rotated which two deep transaction properties timed
out. Resuming the capped database also closed them, but the 32-job result is
the preferred standalone stress artifact. It confirms that the old
inconclusives were portfolio-resource limitations rather than property or
model failures.
